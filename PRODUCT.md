# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Anyone who needs a quick fix to a PDF: reorder, rotate or delete pages, merge several files into
one, highlight something, or remove a piece of text or an image before passing the file on. They
come with a concrete file and a small job, want it done in a minute, and don't want to upload the
file to a website, create an account or install anything.

Privacy is a strong bonus for everyone and decisive for some: people with contracts, IDs, bank
statements, medical or HR papers, who mark private parts or delete them before sharing.

## Product Purpose

PDF Studio edits PDFs entirely in the browser: open, change, download a new file. Success is a
user who opens a file, does the job without reading instructions, and downloads a result that
contains exactly what the editor showed, nothing more.

Today it is a page organizer with light content editing. The direction is a full PDF editor
(vector drawings, groups, fonts, forms; see [ROADMAP.md](ROADMAP.md)), without giving up the
principles below.

## Positioning

- **Files never leave the device.** Not as a promise: the page's Content Security Policy blocks
  every request to another server, so a file can't be sent anywhere even by mistake. No server,
  no account, no upload.
- **Removed means removed.** Deleted pages, text and images are taken out of the file, not
  covered or left behind as unused objects. Links between pages are cut so a deleted page can't
  come back. Private marks black out by default: what is under them is cut out of the text and
  the images, and a black box is drawn.
- **Works offline and installs as an app**, from a static site with no build step.
- **Free and open source** (MIT).

## Operating Context

- Mostly used on a desktop or laptop, with a mouse or trackpad and the keyboard, often with a
  file dragged in from the file manager or a mail attachment. Opened as a PDF handler when
  installed (`file_handlers` in the manifest).
- Phones and tablets must work for the core page operations (open, reorder, rotate, delete,
  download); they are not the main target for detailed editing.
- Sessions are short and single-purpose. Nothing is stored between sessions; closing the tab
  discards the work.
- Privacy marks are exported as standard PDF highlight annotations and as a JSON list
  (`pdf-studio-privacy/1`, documented in the README). The list is an open format for any
  pseudonymization tool; there is no particular consumer.

## Capabilities and Constraints

- Features: see the README. In short: open several PDFs (also password-protected ones), arrange,
  rotate and delete pages, Details view with highlights, privacy marks, selecting, changing and
  deleting objects, undo/redo, download with optional AES-256 password, install, offline.
- Every action is reachable by keyboard; touch works by tap and press-and-hold.
- Static site: plain HTML, CSS and JavaScript modules, no framework, no build step. pdf.js
  (previews) and pdf-lib (result) are vendored in `vendor/`. Parsing and export run in a web
  worker.
- Must work on plain `http://` on a local network, so it can't rely on Web Crypto (crypto is in
  plain JavaScript); offline and install need `localhost` or HTTPS.
- Memory is the main resource limit, on phones in particular (see the robustness section of
  [ROADMAP.md](ROADMAP.md)).
- Known limitations are listed in the README (certificate-protected PDFs, bookmarks, links and
  form fields not carried over).

## Brand Commitments

- Name: **PDF Studio**. Icon in `icons/icon.svg`.
- Voice, as in the current UI and README: plain, short sentences that say what happens and what
  doesn't ("Marks only annotate; they do not remove anything."). Honest about limits, no
  marketing superlatives.
- Light and dark mode.

## Product Principles

1. **Nothing leaves the device.** No feature may need a server, an account or a network request
   to another origin.
2. **What you see is what you download.** The editor shows the rewritten page; the result
   contains exactly that, and removed content is really gone.
3. **The quick job stays quick.** Open, fix, download without setup or instructions. Growing
   toward a full editor must not bury the page operations.
4. **Desktop first, phone never broken.** Detailed editing is designed for desktop; the core page
   operations must work on a phone.
5. **Say what happens.** Be explicit about what an action does, what it doesn't do and where the
   limits are.
